# שלב 2 – משתמשים, תפקידים, כניסה (דוח)

> CHECKPOINT 2 (ביקורת Fable על שלב 1) טרם אושר רשמית; המשתמש הנחה להמשיך.

## מה נבנה
- מטריצת הרשאות לפי PRD סעיף 3 + בדיקת snapshot שנכשלת בכל הרחבה בטעות (`tests/unit/permissions-matrix.test.ts`).
- `auth_tokens` (הזמנה / איפוס / קוד SMS), migration 0002. נשמר hash בלבד, חד-פעמי, עם תוקף; קוד SMS ננעל אחרי 5 ניסיונות (`lib/services/tokens.ts`).
- Auth.js (Credentials, JWT: id, organizationId, roles). `proxy.ts` מפנה לכניסה (אופטימי; ההרשאה האמיתית בשרת).
- מסכים (עברית + אנגלית): כניסה, שכחתי סיסמה, איפוס, הזמנה, בית לפי תפקיד, יציאה.
- `/manager/users` + `lib/services/users.ts`: הזמנה, כמה תפקידים, השבתה/הפעלה, שליחה מחדש, שיוך סטודנטים לרכז (בודד/בכמות, הכל או כלום). הכל ב-audit_log.
- גישה לנתונים לפי תפקיד: `listUsers/getUser` מסננות לפי ארגון ודרך מנוע ההרשאות.

## כללים שנאכפים
- תמיד נשאר מנהל פעיל; אי אפשר להשבית את עצמך.
- הסרת תפקיד רכז מנתקת ממנו את הסטודנטים; רכז חייב להיות רכז פעיל באותו ארגון.
- כניסה לא חושפת אילו מיילים רשומים; איפוס סיסמה נותן אותה תשובה בכל מקרה.
- `sendLink` / `safeNext` ב-`lib/services/auth-links.ts` (לא "use server") כדי שלא ייחשפו כפעולות שרת.

## פתוח
- אין הגבלת קצב לניסיונות כניסה עם סיסמה (קוד SMS כן מוגבל). לפני עלייה לאוויר.
- אותו מייל בשני ארגונים: נבחר הראשון. דורש פתרון כשיהיה יותר מארגון אחד.
- הרשמה עצמית (`/register`) ושליחת SMS בפועל: שלב 3. ספקי מייל/SMS עדיין קונסול.
- RLS כשכבה שנייה, סיבוב סיסמת Neon, חיבור repo ל-Vercel: פתוחים. לא הועלה preview לשלב 2 (אין remote).

## תיקוני ביקורת Fable (docs/review-stage-2.md)
1. **הסלמת הרשאות:** פעולה חדשה `manage` על `user` (מנהל בלבד) ל-`setRoles`/`setStatus`/שליחה מחדש. הסטודנט נשאר עם `update user own` רק לפרופיל. נבדק לכל תפקיד, כולל על עצמו.
2. **session:** ה-JWT מחזיק רק מזהה; `getActor()` (`lib/session.ts`) קורא תפקידים וסטטוס מה-DB בכל בקשה (cache לבקשה). השבתה והסרת תפקיד נכנסות לתוקף מיד. כל דף תפקיד עובר `requireRole`. e2e מוכיח: השבתה → הבקשה הבאה מופנית לכניסה.
3. **איפוס/הזמנה למשתמש מושבת:** `setPasswordFromToken` (`lib/services/credentials.ts`) דוחה ומחזיר את הטוקן (rollback). בדיקת אינטגרציה.
4. כל בדיקות ההרשאה עוברות דרך `can`; אין עוד `roles.includes("manager")` בפעולות.
5. נסגרו גם: `lastLoginAt` מתעדכן, `?error=` מוולדט, ניקוי משתמשי e2e בסוף הריצה.
