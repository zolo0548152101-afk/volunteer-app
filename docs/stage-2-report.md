# שלב 2 – משתמשים, תפקידים, כניסה (דוח)

> CHECKPOINT 2 (ביקורת Fable על שלב 1) טרם אושר רשמית; המשתמש הנחה להמשיך.

## מה נבנה
- מטריצת הרשאות לפי PRD סעיף 3 + בדיקת snapshot שנכשלת בכל הרחבה בטעות (`tests/unit/permissions-matrix.test.ts`).
- `auth_tokens` (הזמנה / איפוס / קוד SMS), migration 0002. נשמר hash בלבד, חד-פעמי, עם תוקף; קוד SMS ננעל אחרי 5 ניסיונות (`lib/services/tokens.ts`).
- Auth.js (Credentials, JWT: id, organizationId, roles). `proxy.ts` מפנה לכניסה (אופטימי; ההרשאה האמיתית בשרת).
- מסכים (עברית + אנגלית): כניסה, שכחתי סיסמה, איפוס, הזמנה, בית לפי תפקיד, יציאה.
- `/manager/users` + `lib/services/users.ts`: הזמנה, כמה תפקידים, השבתה/הפעלה, שליחה מחדש, שיוך סטודנטים לרכז (בודד/בכמות, הכל או כלום). הכל ב-audit_log.
- גישה לנתונים לפי תפקיד: `listUsers/getUser` מסננות לפי ארגון ודרך מנוע ההרשאות.

## כללים שנאכפים
- תמיד נשאר מנהל פעיל; אי אפשר להשבית את עצמך.
- הסרת תפקיד רכז מנתקת ממנו את הסטודנטים; רכז חייב להיות רכז פעיל באותו ארגון.
- כניסה לא חושפת אילו מיילים רשומים; איפוס סיסמה נותן אותה תשובה בכל מקרה.
- `sendLink` / `safeNext` ב-`lib/services/auth-links.ts` (לא "use server") כדי שלא ייחשפו כפעולות שרת.
